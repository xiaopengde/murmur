# Murmur · 复盘纪要 Prompt（可选）

> 转录 + 清洗已经搞定？想再多走一步出一份**结构化复盘**？把这份 prompt 连同 `逐字稿-清洗版.md` 喂给 LLM。
> **复盘纪要不是默认产物**——大多数场景只要可读逐字稿就够了。下列模板偏面试/工作会议向，其他场景按需删改。

---

## === PROMPT 开始 ===

我会给你一份已经清洗过的中文逐字稿（会议 / 面试 / 用研访谈）。请基于它输出一份结构化的**复盘纪要**，帮我快速定位"哪些地方答得好 / 哪些地方答得拉 / 漏掉了什么 / 下次应该怎么改"。

### 复盘原则

1. **每个观察必须能映射回逐字稿的具体段落**，必要时引用一两句原话作为证据
2. **不要写空话**——"沟通有待加强"、"细节需要丰富"这种放之四海皆准的废话不写
3. **批评要具体到字句**，赞扬要说清楚"哪里好"
4. **如果当事人主动 push back 你的某个判断，先信他/她**——他/她在现场，你只看到文本
5. **保留中英混写**，专业术语别硬翻

### 输出模板（按需删减章节）

```markdown
# <场景名> · 复盘纪要

## 1. 结构与时长

- 总时长：约 XX 分钟
- 各章节占比（凭逐字稿章节）：
  - 第 X 节 ≈ X% 时长
  - ...
- 节奏判断：是不是某个话题花了不该花的时间？某个该展开的地方匆匆带过？

## 2. 议题清单 / 问题清单

把对方（面试官 / 主持人 / 访谈者）问的所有问题列出来：

| # | 问题 | 你怎么答的 | 答得好 / 拉 / 一般 |
|---|---|---|---|
| 1 | ... | ... | ... |
| 2 | ... | ... | ... |

## 3. 答得好 / 推进顺利的地方

针对每个亮点：
- **亮点 X**（对应逐字稿哪段）：具体好在哪
- 引用一句关键原话作为证据

## 4. 答得拉 / 卡住 / 没接住的地方

针对每个问题：
### 4.X <问题简述>
- 引用原话片段
- 问题诊断：是 framing 不对？数据/细节不够？口播结构混乱？心态炸了？术语用错？
- **改法**：下次遇到同类问题应该怎么答（具体到结构 / 数字 / 例子）

## 5. 漏问 / 漏覆盖的点

我自己漏说的、对方没追问到但其实有用的内容（结合自己的项目背景判断）。

## 6. 反问环节复盘（仅面试场景）

| # | 我的问题 | 对方回答 | 评分 / 原因 |
|---|---|---|---|

如果反问质量差异大，分析：哪个反问最 sharp、哪个被对方 dodge 了、哪个暴露了对方/团队的信号。

## 7. 给项目素材 / prep doc 的补丁

基于这次暴露的问题，下次准备应该补：
1. ... （具体到补什么数字 / 例子 / 故事）
2. ...

## 8. 整体结论

3-5 句话总结：这场整体什么水平、最大的进步是什么、最大的待改是什么、要不要进下一轮 / 要不要重做。
```

### 我的逐字稿如下：

（在这里贴 `逐字稿-清洗版.md` 的全部内容）

请按上述模板输出复盘纪要。

## === PROMPT 结束 ===

## 使用提示

- **场景不是面试**：把章节 6（反问复盘）删掉，改成 "对方反馈 / 待跟进事项"
- **场景是用研**：章节 4 的"答得拉"改成"用户表达模糊 / 没说清需求的地方"，章节 7 改成"下次访谈提纲补丁"
- **想让 LLM 给得更狠**：在 prompt 末尾加一句"批评的时候不要客气，假设我是你的徒弟，你看了我的录像后准备给我一顿狠的"
- **想要中性 / 鼓励向**：加一句"语气保持中性，重点是可执行的下一步而不是评判"
